F1

Multi-Agent Orchestration System

Prioridad crítica ★★★★★

Por qué: lo piden las ofertas de mayor valor (Arzurus, AI Agent roles). Demuestra que vas más allá de un solo agente y te diferencia de “zap builders”.

Qué construir

  • Agente 1: extrae y estructura datos de fuentes diversas.
  • Agente 2: analiza calidad / SEO / patrones.
  • Agente 3: verifica hechos contra fuentes externas.
  • Agente 4: genera recomendaciones accionables.
  • Orquestador: distribuye según tipo de input, consolida, maneja conflictos.

Características clave

  • Agentes que se revisan entre sí (agent reviewing agent).
  • Permisos granulares por agente.
  • Logs transparentes de cada decisión del orquestador.
  • Confidence scoring por agente y por output final.
  • Human-in-the-loop en resultados de baja confianza.

Stack: Claude API, Next.js, Supabase, MCP (opcional pero ideal) · 2–3 semanas · Demo: video 3–5 min con flujo completo y logs.

F2

Custom MCP Server Builder

Prioridad alta ★★★★★

Por qué: ofertas técnicas lo piden explícitamente. Demuestra que construyes infraestructura, no solo usas herramientas. Skill escaso.

Qué construir — 2 a 3 MCP servers

  • Server 1 — Google Workspace: Calendar (lectura/escritura controlada), Gmail (búsqueda/análisis), creación de eventos con validación, permisos por operación.
  • Server 2 — Database Query Engine: Supabase/PostgreSQL, queries en lenguaje natural, validación previa, logging de operaciones.
  • Server 3 — Public API Gateway: clima / datos económicos, normalización, cache inteligente, rate limiting.

Cada tool call auditado y logged. Documentación técnica, ejemplos en README, código limpio.

Stack: TypeScript, MCP SDK, Node.js · 1–2 semanas · Demo: GitHub público + README técnico.

4. Consejos clave para destacar

4.1 Cada proyecto debe tener siempre

  • README técnico: arquitectura (diagrama), stack, install local, env vars, decisiones clave.
  • Video demo 2–3 min: sistema funcionando, problema que resuelve, features clave; hablar natural, no leer guion.
  • Código limpio: comentarios en lo complejo, nombres descriptivos, carpetas lógicas, sin código muerto.
  • Live demo si es posible: Vercel/Netlify, datos de ejemplo, instrucciones claras.

4.2 Enfócate en mostrar tu diferenciador

Arquitectura, no solo código

Flujos de datos, comunicación entre componentes, decisiones de diseño.

Confidence scoring

El sistema sabe cuándo no sabe. Evidence tagging. Checkpoints humanos.

Auditabilidad

Logs transparentes. Cada decisión trazable. Debugging fácil.

Human-in-the-loop

Cuándo pide ayuda. Cómo escala de AI a humano. No es automatización ciega.

4.3 No construyas todo desde cero

  • AI Bid/No-Bid → RFP Tracking Platform.
  • Confidence-Scored Extraction → extracción de datos healthcare.
  • Hermes Mini → Executive Reporting para otros dominios.
  • Ahorro estimado: 40–60% menos tiempo por proyecto.

4.4 Reglas de oro al aplicar a ofertas

Nunca

  • Nombrar clientes (usa descripciones genéricas).
  • Fabricar testimonios o experiencia.
  • Sonar débil sobre herramientas que puedes aprender.
  • Usar guiones largos (—) en covers (señal de IA).
  • Decir “I'd love to be considered”.

Siempre

  • Abrir con hook de resultados concretos.
  • Métricas verificables (90%, 91%, $800/mes).
  • Historia de origen (call center → AI) cuando aplique.
  • Detalle técnico específico; frases exactas del cliente.
  • Anclar tarifa ($15–18/hr) desde el inicio.
  • Manejar brechas con criterio, no disculpas.

4.5 Seguridad — líneas rojas

  • Nunca: prefijo NEXT_PUBLIC_ para secretos; hardcodear API keys; commitear credenciales; pagos fuera de Upwork (viola ToS).
  • Siempre: env vars con scope; keys por entorno (dev/staging/prod); least-privilege; pagos dentro de Upwork.

4.6 Disponibilidad y tarifa

Horario: lunes a sábado, máximo 40–42 hrs/semana. Nunca domingos (innegociable). Overlap con US Eastern/Central (UTC-5).

Tarifa: propuesta estándar $15–20/hr. Piso de descarte: $11/hr como máximo del rango. Complejos: $18/hr es el sweet spot. Ancla la tarifa en la primera propuesta.

4.7 Scripts de video — sonar natural

Haz esto

  • Frases cortas con pausas.
  • Muletillas ocasionales (“like”, “so yeah”).
  • Lenguaje simple; explica la idea, no memorices.
  • Una toma, sin sobre-editar.

Evita esto

  • Sonar memorizado o robótico.
  • Jerga técnica encadenada difícil de decir.
  • Leer el guion palabra por palabra.
  • Sobre-producir el video.
